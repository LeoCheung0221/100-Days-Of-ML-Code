# 第一阶段日课 · 排版与叙事规范

读者：**量化研究 / 交易开发工程师**（及需审计数字的协作方）。文风：结论先行、机制清楚、可复现，避免科普腔与元叙事。

## 结构（中文四段）

| 区块 | 作用 | 必备元素 |
|:---|:---|:---|
| **费曼法讲解** | 动机与机制 | 简短 blockquote（结论/合同）、**≥1 个 `mermaid`** |
| **核心知识** | 可审计 | **` ```text` 中有一段与脚本 stdout 逐行一致**、表、必要公式 |
| **拓展领域** | 深度 | 与因子/回测/文献的真实联系；**不编造引用** |
| **实战总结** | 复现 | 命令、核对键值 |

## 字数

- 中文汉字 **3000–5000** 为默认目标；机制复杂日可更长。
- 禁止模板复读（`verify_season01_docs.py` → `FORBIDDEN_ZH`）。
- **不要**「讲给非程序员」「路人一句话」「培训同事」等与工程无关的段落。

## Mermaid

- 每课至少 1 幅；节点用 **短中文或符号**，数字 **必须来自 stdout**。
- 类型：`flowchart`（数据/估计路径）、`sequenceDiagram`（时序/切分）、必要时 `xychart-beta`（与脚本列一致）。

## 排版

- 可用少量 emoji 作 **段标题标记**（📈 🔢），不堆砌。
- `>` 仅用于 **结论、合同、常见误用** 一句打住。
- 数字纪律：正文小数来自当日 stdout 或同块可核对行。
