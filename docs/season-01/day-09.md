# 第 9 天 · 打乱日期

[第一阶段 · 模型](README.md) · 可运行

今天的学习要点：五个配对原样保留，只把行序改成 `[2, 4, 3, 0, 1]`。斜率和残差平方和不变，仍是 `3.2700x − 1.2900` 和 96.3390。这是批量最小二乘对行序的不变性，不是模型忽略了时间。

## 费曼法讲解

第 8 天改变的是进入方程的集合，斜率从 2.0500 变成 8.0500。今天不改变集合。五个「第几天，收盘」的配对原样留着，只打乱它们在表里的上下顺序，再做一次批量最小二乘。

打乱之后的行序，用从 0 开始的下标写，是 `[2, 4, 3, 0, 1]`。第三行被拿到最上面，但那一行仍然是第三日配 6.2，没有把第三日的收盘安到另一天上。正规方程对行求和。求和与加总顺序无关，所以系数应该不变。打印出来的直线仍是 `ŷ = 3.2700x − 1.2900`，平方和仍是 96.3390。斜率的差是 `1.332e-15`，平方和的差是 `1.421e-14`，这是浮点噪声，不是一条新的直线。若有人把 `1.332e-15` 写成「打乱使斜率上升了一点点」，他把舍入误差读成了经济上的变化。两个差都留在打印里，解读是不变。配对若被拆开，这两个差不再接近零，那是另一道题，今天的脚本没有拆配对。行序可以变，`(t, y_t)` 这一对不能拆。

这件事很容易被说成「模型不看时间」。那个说法是错的。横坐标仍然是 `x_t = t`，第一天和第五天在设计矩阵里不是同一个数。时间进了方程。没进方程的是表的排版顺序。把配对拆开，让第五天的收盘跟第一天的横坐标绑在一起，那是另一道题，今天不做。配对必须保持完整。

## 核心知识

原顺序上的批量最小二乘：

```text
ŷ = 3.2700x − 1.2900
RSS = 96.3390
```

行序改为 `[2, 4, 3, 0, 1]` 之后，再解一次。斜率和残差平方和的差：

```text
Δslope = 1.332e-15
ΔRSS = 1.421e-14
```

设计矩阵的每一行仍是 `[t, 1]`，标签仍是该 `t` 的收盘。交换行，是交换求和的项。`XᵀX` 和 `Xᵀy` 在精确算术下不变，`lstsq` 给出的系数因此不变。浮点差留在 `1e-14` 这一量级，不能解读成「打乱之后斜率略有变化」。

第 8 天的窗口也是按日期收集行，不是按表的当前位置收集行。只要配对不拆，把窗口里的三行上下对调，窗口系数同样不变。不要说成：行序一乱，第 8 天的窗口斜率就会从 2.0500 变成别的数。窗口变，是因为集合从 `{1, 2, 3}` 换成了 `{2, 3, 4}`。行序变而配对还在，集合没变。

## 拓展领域

面板和逐笔数据进回归之前常要排序：按时间、按股票、按成交。排序是为了让滞后、滚动窗口和交易日对齐写起来不容易错。排序本身不是一个特征。批量最小二乘读的是配对 `(x, y)`，不读「这一行现在排在第几」。把排序的结果又当作一列输入，或者打乱时把标签和特征拆开，才会改变估计。

时间序列模型会在别的地方依赖顺序。滞后项 `y_{t-1}` 必须按时间去取前一行的标签，而不是按打乱之后的上一行。今天的横坐标是日期编号本身，已经写在行内，所以交换行不交换信息。若特征是「表里上一行的收盘」，打乱就会把昨天换成一个无关的日子。那是特征定义变了，不是最小二乘突然开始看行序。写滞后之前，先把行按时间排好，再取上一行。今天没有构造那样的滞后列。
