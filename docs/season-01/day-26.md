# 第 26 天 · 随机切分

[第一阶段 · 模型](README.md) · 可运行

今天的学习要点：种子是 1，训练比例是 0.70。在训练行上把今日收益对昨日收益做最小二乘，测试集上的方向准确率是 0.4583。这个数是对照。今天只把它标成对照。

## 费曼法讲解

样本仍是 AAA 上有限复权收盘的简单收益。昨日收益是自变量，今日收益是因变量，一对滞后构成一行。第 25 天把昨日收益原样当作预测，斜率和截距都不估。今天改成在一部分行上估计一条直线，再在其余行上看符号。

哪些行进入训练，由种子 1 的随机数决定。训练比例写死为 0.70，无放回抽取。没有抽中的行是测试。直线只在训练行上做普通最小二乘：今日收益对昨日收益，得到一个斜率和一个截距。测试行套用这条直线，比较预测收益和实际收益的符号。测试方向准确率印成 0.4583。

打印的最后一行是 this number is the control。0.4583 今天的身份是对照。它还没有被放到按时间切开的测试准确率旁边。程序给它的句子只有这一句：这个数是对照。种子、比例和这个准确率，就是今天交出来的全部。

第 25 天的 0.4675 是全样本上「预测等于昨日收益」的符号命中率。今天的 0.4583 是另一条对象：斜率在训练行上估出来，符号只在测试行上数。两个四位小数接近，回答的不是同一次计数。今天不把 0.4583 和第 25 天的 0.4675 合成一个结论，也不把它和后面才会出现的时间切分放在同一句里。

## 核心知识

```text
split = random, seed 1, train fraction 0.70
test direction accuracy = 0.4583
this number is the control
```

记一行为 `(x_t, y_t) = (r_{t−1}, r_t)`。训练掩码由种子 1 无放回抽出，抽出的比例是 0.70。在训练行上，

```text
ŷ = β̂₀ + β̂₁ x
```

系数只由训练行的最小二乘决定。测试方向准确率是测试行上 `sign(y) = sign(ŷ)` 的比例，印成 0.4583。

0.4583 的定义里有三件已经写死的事：种子 1、训练比例 0.70、以及分数只在测试行的符号上计算。换种子会换成另一批训练行，准确率可以变成别的四位小数。今天不换。打印出来的对照就是这一个 0.4583。

这个数今天不与时间切分并排。并排是下一步的工作。今天的句子停在程序已经印出的那一行：this number is the control。

## 拓展领域

随机切分把行打散之后再估系数，测试行在时间上可以落在训练行的前面，也可以落在后面。对一条按日期排列的收益序列，这种打散回答的是：在这一种抽法下，测试符号准确率印成多少。它不回答「训练全部发生在测试之前」时准确率是多少。那一问留给下一天。今天若提前把两个数写在一起，对照就不再是对照，而变成一次比较的一侧。程序没有做这次比较。

0.4583 也不是第 22 天那种不估参数的滞后符号。滞后符号的规则在计数之前就已经是「昨日的符号」，分母是全部可比较的段。今天的符号来自一条只看见训练行的直线。测试行的标签没有进入 `β̂`。这是它能够被叫做测试准确率的原因。它被叫做对照，是因为今天的笔记只给它这一个身份。

种子写在程序里，是为了让再跑一次仍然抽出同一批行。比例 0.70 同样写死。两者都不是看到 0.4583 之后再调的旋钮。对照的数值因此可以复读：同一文件、同一种子、同一比例，测试方向准确率仍是 0.4583。今天不再给 0.4583 加第二句身份。

与第 9 天行序不变性的分野要反复核对。第 9 天打乱的是同一设计矩阵里的行顺序，五个 `(t, y)` 配对不变，`β̂` 与 RSS 在浮点噪声内不变。第 26 天打乱的是哪些行进入训练掩码：测试行的标签没有进入 `β̂`，但每一行仍是 `(r_{t−1}, r_t)` 这一对。若在面板工程里对含滞后特征的全表做 `sample(frac=1)` 再切分，破坏的是特征构造所依赖的时间顺序，不是今天这种「掩码不同、配对仍在」的设定。今天的脚本只有一阶滞后，且切分发生在配对已经写定之后，因此 0.4583 只回答这一种随机掩码下的测试符号比例。

与第 22 天滞后符号的对照也要并排读。第 22 天的规则在计数之前就已经固定为「用昨日收益的符号」，分母是全样本上可比较的步数，打印是 0.4675，不估斜率。今天的符号来自训练行上估出的 `β̂₀ + β̂₁ r_{t−1}`，只在测试行上数 `sign(y)=sign(ŷ)`，打印是 0.4583。两个四位小数接近，容易在报告里被合成一句「差不多」。合成会丢掉对象：一个是无参数基线，一个是随机掩码下的留出符号。今天 deliberately 只给 0.4583 对照身份，不与第 27 天的时间切分 0.5417 并排，就是为了不让对照在印出来之前就变成比较的一侧。

工程上写随机切分时，至少应同时报告种子、比例、以及测试行是否可能早于训练行。今天三样都写在打印里：种子 1、比例 0.70、以及测试方向准确率 0.4583。若读者只抄 0.4583 进结果表，而不抄种子与比例，别人无法复现同一批训练行。复现不了，0.4583 就不是对照，只是一个孤立的四位小数。第 37 天会在混切里让随机切分看起来更高，那是跨股票共享日期的另一个设计；第 26 天单标的上的 0.4583 不能被那一天的 0.7234 替换或覆盖。

双精度下，训练行上的 `lstsq` 与测试行上的符号比较是分开的两步。第一步只看见训练行的 `(r_{t−1}, r_t)`；第二步把同一个 `(β̂₀, β̂₁)` 用到测试行，比较的是符号而不是水平 RSS。因此 0.4583 不是样本内拟合优度，也不是第 1 天那种 five-point RSS。把它与任何样本内平方和并列，都会把评分对象搞混。第 10 天已经说明方向与水平残差可以落在不同日子上；今天的方向分数同样不能从水平拟合好坏直接推出来。

面板机器学习里，「随机切分」常被误当成一种中性的交叉验证。对独立同分布样本，它估计的是泛化误差。对时间序列或面板滞后特征，它额外混合了时间逆序：测试行可以比训练行更早。今天的 0.4583 就是在这种逆序允许的协议下，对测试行符号的计数。它既不证明策略无效，也不证明有效；它只是一个可复现的对照点，等待与时间切分并排。工程交付时应把协议写进 README：种子 1、比例 0.70、特征为滞后收益、测试指标为方向命中率。缺任何一项，0.4583 都无法被他人核对。

 sklearn 的 `train_test_split(shuffle=True)` 在时序项目里默认危险，原因不在 OLS 公式，而在行与时间的对应。今天的脚本刻意简单：一条直线、一个滞后。复杂 pipeline 若在切分后构造滚动特征，仍可能在训练段内正确、在测试段内悄悄用到未来。第 40 天的六行清单是特征来源的审计；第 26 天是切分协议的审计。两层都要，不能互相替换。

 写论文或内部 memo 时，避免用「交叉验证准确率 0.46」而不说明是 random row split on lagged returns。审稿人或未来的你会把 0.4583 误读为 walk-forward 成绩。对照句 this number is the control 的存在，就是要求报告里保留「尚未与时间切分比较」的状态。第 27 天之后，句子才升级为并排两数，但 0.4583 的身份仍可追溯为第 26 天的对照，而不是「失败的模型」。

## 实战总结

```bash
python days/26-random-split/random_split.py
```

脚本打印 `split = random, seed 1, train fraction 0.70`、`test direction accuracy = 0.4583`、`this number is the control`。实现是 [`random_split.py`](../../days/26-random-split/random_split.py)。

测试方向准确率 0.4583 是对照。种子是 1，训练比例是 0.70，系数来自训练行上的最小二乘。今天不把这个数放到时间切分旁边。下一步改成按时间切，测试全部落在训练之后，两个准确率都要印出来。

交作业时写三句即可核对：训练掩码来自种子 1、比例 0.70；测试符号只在未进入训练的测试行上计数；最后一行仍是 this number is the control。不要写「随机切分证明了模型无效」，0.4583 今天没有任何「有效/无效」的判决，只有对照身份。不要写「与第 25 天 0.4675 几乎一样所以规则等价」，两个计数对象不同。复现时应用仓库内与第 1 天相同的 `numpy==1.24.4`；换种子会得到别的四位小数，那就不是第 26 天的对照。给工程师的阅读顺序：先跑第 25 天确认无参数基线，再跑第 26 天单独看 0.4583，第 27 天再并排时间切分 0.5417。写单元测试时，可对固定 `(X,y)` 与固定 `random_state=1` 断言测试掩码比例约为 0.30，且 `fit` 只调用训练行索引；失败常见原因是把 `y` 与 `X` 错位 shuffle，或把测试标签混进 `fit`。
