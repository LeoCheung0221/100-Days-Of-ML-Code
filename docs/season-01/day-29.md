# 第 29 天 · 用未来开盘标准化

[第一阶段 · 模型](README.md) · 可运行

今天的学习要点：泄漏缩放使用全部开盘，包括以后的开盘。收益对泄漏收盘的 RSS 是 0.2642，收益对只用过去收盘缩放的那一列的 RSS 是 0.2650，差是 0.0008。两份 RSS 用同一个有限掩码。泄漏的识别依据是以后的开盘进入了缩放的自变量，不是分数变得更好。

## 费曼法讲解

仍是 AAA 上有限的收盘和开盘。泄漏缩放把每一个收盘都减去全部开盘的均值，再除以全部开盘的标准差。全部开盘包含这一行之后的开盘。所以较早那一天的缩放值，是以后开盘的函数。一个在当时还没有发生的开盘，已经进入了这一天的特征。

对照的缩放只用过去。下标从 5 起，当天的缩放值用该行之前的收盘计算均值和标准差，不含当天，也不含以后的开盘。前面不够长的那些行没有定义，留成空。要解释的是简单收益。两条样本内直线分别用泄漏后的收盘、以及只用过去的收盘，去拟合收益。

两份残差平方和使用同一张掩码：过去缩放已经有定义的那些行。泄漏缩放在这些行上也有定义，因为它对每一行都用了全部开盘。在这张共同的掩码上，收益对泄漏收盘的 RSS 是 0.2642，收益对过去收盘缩放的 RSS 是 0.2650。两者相差 0.0008。

0.0008 很小。它不构成「泄漏拟合更好」的证据，今天也不把 0.2642 写成优于 0.2650 的成绩。第 28 天的同日最高价把平方和拉低了 3.6518，差距一眼可见。今天的差距贴在第四位小数上。若识别泄漏要靠平方和明显下降，0.0008 会被放过去。识别依据写在缩放的定义里：泄漏缩放的均值和标准差以以后的开盘为自变量。打印的最后一行是 the leaky scale is a function of later opens。

## 核心知识

```text
leaky scale uses every open, including later ones
RSS of return on leaky close = 0.2642
RSS of return on past-only close = 0.2650
the leaky scale is a function of later opens
```

记开盘序列为全部行上的 `open`。泄漏特征是

```text
z_t = (close_t − mean(open)) / std(open)
```

`mean(open)` 与 `std(open)` 用到序列里每一个开盘，包括 `t` 之后的开盘。过去特征从下标 5 起才有定义：

```text
z_t^{past} = (close_t − mean(close_{s < t})) / std(close_{s < t})
```

窗口是该行之前的收盘。收益 `r` 对 `z` 和 `z^{past}` 分别做带截距的样本内最小二乘。掩码是 `z^{past}` 有限的那些用于回归的行，两份 RSS 共用它。

```text
RSS(r ~ z) = 0.2642
RSS(r ~ z^{past}) = 0.2650
差 = 0.0008
```

差是 0.0008。两份平方和几乎挨着。泄漏是否成立，看 `z_t` 的自变量里有没有以后的开盘。有，所以这是泄漏缩放。0.2642 与 0.2650 的高低不参与这个判定，也不把较低的那一个升为更好的分数。共同掩码保证两个平方和没有因为行数不同而不可比。可比之后，识别仍然来自定义，不来自 0.0008。

## 拓展领域

标准化看起来只是减一个均值、除一个标准差。均值和标准差若用整段样本来算，整段里时间上靠后的观测会进入靠前那一天的特征。开盘是价格。以后的开盘进入今天的缩放，今天的特征就含有以后的价格水平。再拿这个特征去拟合收益，拟合用到的列在日历上并不干净。

平方和可以几乎不动。0.2642 与 0.2650 只差 0.0008。一个只盯着「RSS 有没有明显变小」的阅读，会把这两列当成差不多的拟合。定义上它们不一样：一列是全部开盘的函数，一列是过去收盘的函数。差不多的平方和不取消这个差别。第 28 天用一个很大的下降 3.6518 展示同日信息。今天用一个很小的差 0.0008 展示另一句：泄漏的识别可以与平方和几乎不变同时成立。

掩码必须相同，否则 0.0008 本身会混进行数的差别。过去缩放在序列开头没有定义，泄漏缩放处处有定义。若让泄漏缩放用上那些开头的行，而过去缩放不用，两个 RSS 的样本就不再是同一批收益。程序先取过去缩放有限的掩码，再让两份回归都落在这个掩码上。因此 0.2642 和 0.2650 是同一批行上的两个平方和。它们的差不负责宣布谁更好。宣布泄漏的是：缩放读进了以后的开盘。

与第 33 天的对照：第 33 天泄漏在「全样本矩看见测试段」，测试 MSE 仍都是 0.000109。今天泄漏在「以后的开盘进入缩放」，RSS 差 0.0008。两种 future=yes 都可以几乎不动分数。识别都靠定义，不靠差值大小。第 40 天两行都会进清单。

工程上 `StandardScaler.fit` 若对整个 `DataFrame` 调用，再 `transform` 训练与测试，就复制了今天的泄漏结构。正确做法是 `fit` 只在训练段，或逐时点只用过去窗口。第 30 天固定 20 日窗口是把信息集写死在长度上；第 29 天是把泄漏写死在「用到了 later opens」。读者应能说出：0.2642 与 0.2650 哪一列的 `μ, σ` 含未来开盘。

Walk-forward 里，第 `t` 天的缩放应只含 `open_{≤t}` 或更严的过去集合。泄漏缩放用 `mean(open)` 全序列，使 `z_t` 依赖 `open_{>t}`。打印句 the leaky scale is a function of later opens 就是判决，与 0.0008 无关。
